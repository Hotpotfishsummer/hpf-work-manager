# 02 · 数据模型

> 对应代码：`backend/app/models/*.py` ｜ 迁移：`backend/alembic/versions/0001_initial.py`、`0002_api_keys.py`、`0003_dev_logs.py`

## 1. 实体关系

```
User (users)
 │
 │ 1:N  owner_id (ondelete CASCADE)
 ▼
Project (projects)
 │
 ├── 1:N  project_id (ondelete CASCADE)  →  Milestone (milestones)
 │                                         │ 1:N milestone_id (ondelete SET NULL)
 │                                         ▼
 ├── 1:N  project_id (ondelete CASCADE)  →  Task (tasks)
 │                                         │ 1:N task_id (ondelete CASCADE)
 │                                         ▼
 │                                       TaskDependency (task_dependencies)
 │                                       · task_id → tasks.id (CASCADE)
 │                                       · depends_on_task_id → tasks.id (CASCADE)
 │
 ├── 1:N  project_id (ondelete CASCADE)  →  DevSession (dev_sessions)
 │                                         │ 1:N session_id (ondelete SET NULL)
 │                                         ▼
 └── 1:N  project_id (ondelete CASCADE)  →  DevLog (dev_logs)
```

DevLog / DevSession 记录开发**过程**（进度/难点/待办/决策/阻塞），与任务、里程碑互补：
git 记"代码状态"，DevLog 记"开发过程"，`related_task_ids` 仅软关联（不设外键），`git_ref` 仅存引用、不解析 git。

## 2. 表结构

| created_at | TIMESTAMPTZ | default now() | UTC |

### projects — 项目

### milestones — 里程碑

### tasks — 任务（核心表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |

### task_dependencies — 任务依赖

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| task_id | INTEGER | FK → tasks.id **ON DELETE CASCADE** + INDEX | 被依赖方（后置任务） |
| depends_on_task_id | INTEGER | FK → tasks.id **ON DELETE CASCADE** + INDEX | 依赖方（前置任务） |

`UNIQUE(task_id, depends_on_task_id)`：同一依赖关系不重复。

### api_keys — AI 工具访问凭证

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| user_id | INTEGER | FK → users.id **ON DELETE CASCADE** + INDEX | 归属用户 |
| name | VARCHAR(100) | | 用途标识（如 "Claude Code"） |
| key_hash | VARCHAR(64) | **UNIQUE** | 明钥的 HMAC-SHA256 哈希（不存明钥） |
| prefix | VARCHAR(16) | | 展示用前缀（`hpf_<prefix>_...`） |
| revoked_at | DATETIME | NULL | 撤销时间；非空即失效 |
| last_used_at | DATETIME | NULL | 最近使用时间（审计） |
| created_at | DATETIME | server_default now() | |

- 明钥格式 `hpf_<6位hex>_<64位hex>`，仅创建时返回一次；落库只存哈希，丢失无法找回
- 校验路径：明钥 → `validate_api_key()` 得哈希 → 按 `key_hash` + `revoked_at IS NULL` 查表

### dev_logs — 开发记录

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| project_id | INTEGER | FK → projects.id **ON DELETE CASCADE** + INDEX | 所属项目 |
| session_id | INTEGER | FK → dev_sessions.id **ON DELETE SET NULL** + INDEX | 归属会话（可空） |
| entry_type | VARCHAR(20) | NOT NULL | `progress/difficulty/todo/decision/blocker/milestone/note` |
| status | VARCHAR(10) | NOT NULL | `open/done`；仅 `todo`/`blocker` 使用 |
| severity | VARCHAR(10) | NULL | `low/medium/high`；仅 `difficulty`/`blocker` 使用 |
| title | VARCHAR(200) | NOT NULL | 一句话标题 |
| content | TEXT | NULL | 详细说明 |
| related_task_ids | JSON | NULL | 关联任务 ID 数组（软关联，不设外键） |
| git_ref | VARCHAR(100) | NULL | commit/分支引用（仅溯源，不解析） |
| author | VARCHAR(50) | NOT NULL | 记录来源（AI 工具用户名） |
| created_at | DATETIME | server_default now() | |
| updated_at | DATETIME | server_default now() onupdate now() | |
| resolved_at | DATETIME | NULL | 标记完成时间 |

> 跨库说明：`related_task_ids` 用 `JSON` 列类型（PostgreSQL 与 SQLite 测试库均兼容），避免依赖 PG 专有 `ARRAY`。

### comments — 评论（任务评论 / 项目指示）

一条评论**恰好**挂在一个锚点上：任务（`task_id`）或项目（`project_id`），由 CHECK 约束保证。

- **任务评论**：对单个任务的讨论。
- **项目指示**：负责人写给「下一次接手该项目的 Agent」的工作方向 / 优先级 / 禁忌 / 结论。
  Agent 通过 `get_project_state.directions` 与 MCP `list_comments(project_id=...)` 读到；
  落实后写 `resolved_at`，之后的 Agent 不再读到，避免旧指示反复被执行。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| task_id | INTEGER | FK → tasks.id **ON DELETE CASCADE** + INDEX + NULL | 所属任务（任务评论） |
| project_id | INTEGER | FK → projects.id **ON DELETE CASCADE** + INDEX + NULL | 所属项目（项目指示） |
| resolved_at | DATETIME | NULL | 项目指示被标记「已处理」的时间；NULL = 仍待处理 |
| author_id | INTEGER | FK → users.id **ON DELETE SET NULL** + NULL | 作者（用户删除后置空，评论保留） |
| author_username | VARCHAR(50) | NOT NULL | 创建时用户名快照（仅显示用） |
| content | TEXT | NOT NULL | 评论正文 |
| created_at | DATETIME | server_default now() | |

> 索引：`ix_comments_task_created (task_id, created_at)`、`ix_comments_project_created (project_id, created_at)`。
> 约束：`ck_comments_exactly_one_anchor` —— `(task_id IS NOT NULL) <> (project_id IS NOT NULL)`。
> 迁移：`0007_project_comments`（同时新增 `tasks.category`，存量按标题关键词保守回填，可改）。
> 作者名走快照而非 JOIN：用户改名/删除后历史评论仍显示当时的作者。

### notification_watermarks — 通知已读水位

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| user_id | INTEGER | PK, FK → users.id **ON DELETE CASCADE** | 一行一用户 |
| last_read_at | DATETIME | NOT NULL, server_default now() | 已读到的最新事件时间（UTC） |
| updated_at | DATETIME | server_default now() onupdate now() | |

> 水位只前推不回退（`PUT` 时取 `max(现值, 新值)`），避免多端并发把已读状态拉回去。

### progress_snapshots — 项目每日进度快照

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| project_id | INTEGER | FK → projects.id **ON DELETE CASCADE** + INDEX | 所属项目 |
| date | DATE | NOT NULL | 快照日期（按 `DISPLAY_TIMEZONE` 判定"今天"） |
| total_tasks | INTEGER | default 0 | 当日任务总数 |
| done_tasks | INTEGER | default 0 | 当日已完成数 |
| progress | FLOAT | default 0 | 数量进度 0-100 |
| weighted_progress | FLOAT | default 0 | 工时加权进度 0-100 |
| created_at / updated_at | DATETIME | server_default now() | |

> 唯一约束 `uq_progress_snapshot_project_date (project_id, date)`。
> **自愈式沉淀**：读取 `GET /projects/{id}/stats` 时按天 upsert，同日只更新不新增，
> 因此不需要额外的定时任务，也不会因服务停机而漏天。
> 数值口径与 `get_project_stats` 完全一致，可直接用于进度趋势图。

## 4. 级联删除策略

| 删除目标 | 影响 | 依据 |
|---|---|---|
| 删除用户 | 级联删除其全部项目（进而级联任务/里程碑/DevLog/DevSession） | projects.owner_id CASCADE |
| 删除项目 | 级联删除其任务、里程碑、DevLog、DevSession | CASCADE |
| 删除里程碑 | **保留**任务，`milestone_id` 置 NULL | SET NULL |
| 删除任务 | 级联删除其依赖记录；DevLog 的 `related_task_ids` 为软关联不受影响 | task_dependencies CASCADE |
| 删除会话 | **保留**DevLog，`session_id` 置 NULL | dev_logs.session_id SET NULL |

> 注意：SQLite（e2e 验证）与 PostgreSQL 对 FK 的被动删除行为一致，均由 SQLAlchemy `passive_deletes=True` + DB 层约束保证。

## 5. 状态机

```
todo ──▶ in_progress ──▶ done
  ▲          │              │
  └──────────┴──────────────┘   （可任意回退）
```

- `todo → done`：进度强制 100，写 completed_at
- `done → 任意`：completed_at 清空，进度保留（非 done 可正常修改）
- 校验层（Pydantic）：status/priority 枚举值白名单，progress 0-100

## 6. 派生数据（不落库）

| 数据 | 计算方式 | 位置 |
|---|---|---|
| 项目进度 % | 完成任务数 / 总任务数 × 100 | `services/stats.py: get_project_stats` |
| 任务是否延期 | status != done 且 due_date < today(UTC) | `services/stats.py: is_overdue` |
| 延期天数 | today - due_date | 同上 |
| 燃尽图 | completed_at 按日累计 | `get_burndown` |
| 甘特图 | tasks + dependencies 映射 | `get_gantt_data` |
| 会话记录数 | COUNT(DevLog) WHERE session_id | `services/dev_logs.py: session_to_dict` |
| DevLog 统计（今日/待办/难点/阻塞/决策） | COUNT + group by entry_type | `services/dev_logs.py: get_dev_log_stats` |
| 开发汇报 | DevLog 按类型分组渲染 Markdown | `services/dev_logs.py: get_dev_report` |

## 7. 迁移管理

```bash
# 生成 SQL（离线验证，无需数据库）
cd backend && alembic upgrade head --sql

# 应用迁移（连数据库）
alembic upgrade head

# 生成新迁移（模型变更后）
alembic revision --autogenerate -m "描述"
```

容器启动时自动执行 `alembic upgrade head`（见后端 Dockerfile CMD）。
