# 02 · 数据模型

> 对应代码：`backend/app/models/*.py` ｜ 迁移：`backend/alembic/versions/0001_initial.py`

## 1. 实体关系

```
User (users)
 │
 │ 1:N  owner_id (ondelete CASCADE)
 ▼
Project (projects)
 │
 ├── 1:N  project_id (ondelete CASCADE)  →  Milestone (milestones)
 │                                         │ 1:N milestone_id (ondelete SET NULL)
 │                                         ▼
 └── 1:N  project_id (ondelete CASCADE)  →  Task (tasks)
                                             │ 1:N task_id (ondelete CASCADE)
                                             ▼
                                           TaskDependency (task_dependencies)
                                           · task_id → tasks.id (CASCADE)
                                           · depends_on_task_id → tasks.id (CASCADE)
```

## 2. 表结构

### users — 用户

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 自增 |
| username | VARCHAR(50) | UNIQUE + INDEX | 登录名 |
| email | VARCHAR(255) | UNIQUE + INDEX | 邮箱（Pydantic 校验格式） |
| hashed_password | VARCHAR(255) | NOT NULL | bcrypt 哈希 |
| created_at | TIMESTAMPTZ | default now() | UTC |

### projects — 项目

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| owner_id | INTEGER | FK → users.id **ON DELETE CASCADE** + INDEX | 归属用户 |
| name | VARCHAR(120) | NOT NULL | |
| description | VARCHAR(500) | NULL | |
| status | VARCHAR(20) | default `active` | `active` / `archived` |
| start_date | DATE | NULL | 项目开始日 |
| end_date | DATE | NULL | 项目截止日（燃尽图/甘特图区间来源） |
| created_at | TIMESTAMPTZ | default now() | |

### milestones — 里程碑

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| project_id | INTEGER | FK → projects.id **ON DELETE CASCADE** + INDEX | |
| name | VARCHAR(120) | NOT NULL | |
| due_date | DATE | NULL | |
| status | VARCHAR(20) | default `active` | `active` / `done` |
| created_at | TIMESTAMPTZ | default now() | |

### tasks — 任务（核心表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| project_id | INTEGER | FK → projects.id **ON DELETE CASCADE** + INDEX | |
| milestone_id | INTEGER | FK → milestones.id **ON DELETE SET NULL** + INDEX | 里程碑删除后任务保留（解除关联） |
| name | VARCHAR(200) | NOT NULL | |
| description | VARCHAR(1000) | NULL | |
| status | VARCHAR(20) | default `todo` | `todo` / `in_progress` / `done` |
| priority | VARCHAR(10) | default `medium` | `low` / `medium` / `high` |
| progress | INTEGER | default 0，0-100 | 单任务进度 |
| start_date | DATE | NULL | 甘特图起点 |
| due_date | DATE | NULL | 截止日（延期判定依据） |
| completed_at | TIMESTAMPTZ | NULL | 完成时间（燃尽图数据源），状态流转时维护 |
| estimated_hours | INTEGER | NULL | **预留**：工时加权扩展 |
| created_at | TIMESTAMPTZ | default now() | |

### task_dependencies — 任务依赖

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| task_id | INTEGER | FK → tasks.id **ON DELETE CASCADE** + INDEX | 被依赖方（后置任务） |
| depends_on_task_id | INTEGER | FK → tasks.id **ON DELETE CASCADE** + INDEX | 依赖方（前置任务） |

`UNIQUE(task_id, depends_on_task_id)`：同一依赖关系不重复。

### api_keys — AI 工具访问凭证

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| user_id | INTEGER | FK → users.id **ON DELETE CASCADE** + INDEX | 归属用户 |
| name | VARCHAR(100) | | 用途标识（如 "Claude Code"） |
| key_hash | VARCHAR(64) | **UNIQUE** | 明钥的 HMAC-SHA256 哈希（不存明钥） |
| prefix | VARCHAR(16) | | 展示用前缀（`hpf_<prefix>_...`） |
| revoked_at | DATETIME | NULL | 撤销时间；非空即失效 |
| last_used_at | DATETIME | NULL | 最近使用时间（审计） |
| created_at | DATETIME | server_default now() | |

- 明钥格式 `hpf_<6位hex>_<64位hex>`，仅创建时返回一次；落库只存哈希，丢失无法找回
- 校验路径：明钥 → `validate_api_key()` 得哈希 → 按 `key_hash` + `revoked_at IS NULL` 查表

## 4. 级联删除策略

| 删除目标 | 影响 | 依据 |
|---|---|---|
| 删除用户 | 级联删除其全部项目（进而级联任务/里程碑） | projects.owner_id CASCADE |
| 删除项目 | 级联删除其任务、里程碑 | CASCADE |
| 删除里程碑 | **保留**任务，`milestone_id` 置 NULL | SET NULL |
| 删除任务 | 级联删除其依赖记录 | task_dependencies CASCADE |

> 注意：SQLite（e2e 验证）与 PostgreSQL 对 FK 的被动删除行为一致，均由 SQLAlchemy `passive_deletes=True` + DB 层约束保证。

## 5. 状态机

```
todo ──▶ in_progress ──▶ done
  ▲          │              │
  └──────────┴──────────────┘   （可任意回退）
```

- `todo → done`：进度强制 100，写 completed_at
- `done → 任意`：completed_at 清空，进度保留（非 done 可正常修改）
- 校验层（Pydantic）：status/priority 枚举值白名单，progress 0-100

## 6. 派生数据（不落库）

| 数据 | 计算方式 | 位置 |
|---|---|---|
| 项目进度 % | 完成任务数 / 总任务数 × 100 | `services/stats.py: get_project_stats` |
| 任务是否延期 | status != done 且 due_date < today(UTC) | `services/stats.py: is_overdue` |
| 延期天数 | today - due_date | 同上 |
| 燃尽图 | completed_at 按日累计 | `get_burndown` |
| 甘特图 | tasks + dependencies 映射 | `get_gantt_data` |

## 7. 迁移管理

```bash
# 生成 SQL（离线验证，无需数据库）
cd backend && alembic upgrade head --sql

# 应用迁移（连数据库）
alembic upgrade head

# 生成新迁移（模型变更后）
alembic revision --autogenerate -m "描述"
```

容器启动时自动执行 `alembic upgrade head`（见后端 Dockerfile CMD）。
