# M3 页面改造规范（给并行改造页面的人）

方法论来源：`docs/design/m3-reference/`（SKILL.md 与 references/）。改页面前至少读
`anti-patterns.md`、`shape-and-elevation.md`、`component-selection.md`、`color-system.md`。

令牌唯一来源：`frontend/src/design/tokens.css`。可复用语义类：`frontend/src/design/global.css`（`.md-*`）。
控件层：`frontend/src/design/element-plus.css`。

## 1. 用户为什么不满意（改造要解决的问题）

- 满屏细边框：每个分区、每张卡、每个标签都描一圈。
- 全是同一种颜色：灰底套灰框，状态/分类/选中态没有区分度。

所以：**用色块区分，不靠边框**。

## 2. 层级怎么表达（按这个顺序选，前面的优先）

| 需求 | 做法 |
|---|---|
| 把相关内容归为一组 | 间距 + 标题（`.md-section`），不套框 |
| 把一块内容提升为「一个整体」（任务卡、指标卡） | 填充式卡片 `.md-card`（`surface-container-highest`，圆角 12，无边框无阴影） |
| 同一卡片里再分一小块 | `surface-container-high` 或 `surface-container`，不要再套一层卡片 |
| 行与行之间分不开 | 分隔线 `.md-divider` / `border-bottom: 1px solid var(--md-outline-variant)` |
| 浮在内容之上（弹层、搜索面板） | `surface-container-high` + `--md-elevation-2` |
| 强调某状态 | 色调容器（下表） |

**不要**：给分区块/工具条/卡片加 `border: 1px solid var(--md-outline[-variant])`（闸门会拦）；卡片套卡片；
到处加阴影；所有东西都做成药丸形。

## 3. 颜色怎么用

- 页面底：`--md-surface`。分区不带底色，卡片才带。
- 主色 `primary` 要**稀缺**：只给当前区域最重要的那一个操作。其余操作用 `secondary-container`（tonal）、
  文字按钮；描边按钮只在需要与相邻主操作区分时用。
- 状态 / 优先级 / 分类 / 选中，一律「容器色 + 该容器上的文字色」成对使用：

| 语义 | 类名 | 背景 / 文字 |
|---|---|---|
| 进行中、选中、信息 | `.md-chip--primary` | primary-container |
| 次要标签、辅助 | `.md-chip--secondary` | secondary-container |
| 完成、健康 | `.md-chip--success` | success-container |
| 注意、待处理、中优先级 | `.md-chip--warning` | warning-container |
| 延期、错误、高优先级 | `.md-chip--error` | error-container |
| 待办、未分类、中性 | `.md-chip--neutral` | surface-container-high |
| 分类（6 类） | `.md-chip--accent-1..6` | 各自的容器色 |

  紧凑版加 `.md-chip--sm`。实心（`.md-chip--solid-*`）只给需要立刻注意的少数地方，如「延期」。
- 分类标签：按 `category` 固定映射到 accent 1–6（新功能→1，排错修复→2，重构→3，测试→4，文档→5，运维部署→6），
  「未分类」用 neutral。
- 文字色只从 `--md-on-surface`（正文）、`--md-on-surface-variant`（次要）、`--md-outline`（占位/禁用）里选。
- 不要用颜色作为唯一的状态信息：状态芯片里保留文字或图标。

## 4. 控件怎么选

| 场景 | 用什么 |
|---|---|
| 一个区域的主操作 | 实心按钮（`el-button type="primary"`） |
| 次要操作 | `el-button plain`（tonal，secondary-container） |
| 低强调 / 行内操作（复制、刷新、查看） | `el-button text` / `.md-btn--text` |
| 筛选（分类、状态、项目） | 筛选芯片 `.md-chip.md-chip--filter`，选中加 `.is-selected`（secondary-container 色块） |
| 只读状态 | `.md-chip--<tone>`，不可点 |
| 图标操作 | `.md-icon-btn`（40×40 点击区，必须有 `aria-label` 或 `title`） |
| 输入 | `el-input` / `el-select`（已是填充式，不要再加边框） |
| 页内切换同级视图 | `el-tabs`（已是指示器药丸样式） |
| 提示 / 建议 | `.md-callout` / `.md-callout--<tone>` |
| 空状态 | 居中文案 + 一个明确的下一步操作，不要虚线框 |

## 5. 字阶

页面标题 `--md-type-headline-sm`（`.page-title`）；分区标题 `--md-type-title-md` 500；
卡片标题 `--md-type-title-md`；正文 `--md-type-body-md`；次要说明 `--md-type-body-sm` + `on-surface-variant`；
芯片/按钮 `--md-type-label-lg`。不要用 600 以上的字重做标题（展示数字可用 `--md-weight-bold`）。

## 6. 约束

- 只改 `<style>` 与模板里的**类名/结构**，不改业务逻辑、接口调用、数据流；事件与 `v-model` 保持可用。
- 不新增 npm 依赖。色值只能出现在 `tokens.css`；缺令牌就报给 lead，不要自己加。
- 完成标准：`cd frontend && npx vitest run tests/design-tokens.spec.ts` 对你负责的文件零输出；
  `npx vue-tsc --noEmit -p tsconfig.app.json` 退出码 0。
- 不要 commit。汇报里写：改了哪些文件、按上面的表做了哪些语义替换、有无缺令牌、有无你拿不准的取舍。
