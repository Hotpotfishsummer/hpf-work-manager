# 08 · AI 接入指南与外部 Agent 导入手册

> 让 Claude Code / Cursor / Antigravity / Windsurf / Cline / dsh 等外部 AI 编码工具，通过 MCP 协议无缝操作任务、项目进度、开发记录（DevLog），并基于「双模态外驱与双重认证」协同推进项目落地，实现多 Agent、多机器的实时看板与代码同步。

## 1. 架构总览

HPF Work Manager 提供两条接入路径：

| 路径 | 适用场景 | 前置要求 |
|---|---|---|
| **MCP Server (44 工具)**（强力推荐） | Claude Code、Cursor、Antigravity、Windsurf、Cline、dsh 等 | 配置 MCP 端点 URL（Tailscale 内网免鉴权或带 API Key） |
| **REST API + API Key** | 自动化脚本 / CI 流程 / 自研轻量工具 | 调用 `/api/keys/exchange` 获取 JWT |

两套路径共享完全统一的业务规则与 PostgreSQL 数据，任何外部 Agent 的写操作（任务创建、双重认证提案、代码交付核销、DevLog 会话）均会通过 **SSE（Server-Sent Events）** 实时推送到网页端看板。

## 3. 认证模式：免鉴权与 API Key

1. **内网免鉴权模式（Zero-Friction Intranet Mode）**：
   - 只要外部 Agent 在 Tailscale 专网或 Localhost 访问，**无需配置任何 Authorization Header**，服务端 `MCPAuthMiddleware` 自动回退以管理员 `admin` 身份放行。
2. **API Key 独立审计模式（Multi-User Mode）**：
   - 在 Web 端（`http://100.69.225.112:8088`）进入「API Keys」页面 ➜ 点击「新建 Key」➜ 生成形如 `hpf_ab12cd_<64位hex>` 的密钥。
   - 请求头配置：`Authorization: Bearer <你的API Key>`。

## 4. 主流外部 Agent 客户端导入配置

### 4.1 Claude Code CLI

#### 命令行一键导入：
```bash
# 局域网/Tailscale 免鉴权导入
claude mcp add --transport http hpf-work-manager http://100.69.225.112:8088/mcp

# 或携带 API Key 导入
claude mcp add --transport http hpf-work-manager http://100.69.225.112:8088/mcp \
  --header "Authorization=Bearer hpf_ab12cd_你的密钥"
```

## 5. 完整 MCP 工具矩阵（28 个工具，2026-11-25 由 44 个合并瘦身）

### 5.1 AI Driver & 双重认证协同工具（4 个，核心演进）

| 工具名 | 参数 | 核心功能与防呆机制 |
|---|---|---|
| **`get_manager_status`** | 无 | 查询算力配额、驱动模式（`DUAL_CERTIFIED` vs `EXTERNAL_DRIVEN`）、工作区物理路径与动态行动准则 |
| **`get_next_steps`** | `project_name: str` | 获取下一步高价值落地任务建议。内部有额度时走 MiniMax 推演，额度耗尽时自动降级为 0-Token 本地代码库启发式规则 |
| **`propose_task_plan`** | `project_name: str`, `tasks: list`, `auto_create: bool = False` | 提报规划方案，内部 MiniMax 充当架构质检员执行 Cross-Audit，拦截幻觉、防乱排期，通过后可一键创建入库 |
| **`verify_and_complete_task`** | `task_id: int`, `git_ref: str`, `verification_evidence: str`, `summary: str = ""` | **【防假交付核心】** 外部 Agent 交付任务时，必须提供真实 Git Commit Hash 与验收证据，自动更新 100% 并写入 DevLog |

> 原 `brainstorm_ideas` / `sync_local_projects` 已移出 MCP，走前端 UI 或 REST（`/api/ideator/brainstorm`、`/api/ideator/sync-projects`）。

### 5.2 项目 / 任务 / 里程碑管理（15 个）

- 项目管理：`list_projects`, `get_project`, `create_project`, `update_project`, `delete_project`
- 里程碑管理：`list_milestones`, `create_milestone`, `update_milestone`, `delete_milestone`
- 任务管理：`list_tasks`, `get_task`（含 `depends_on_detail` 依赖富信息）, `create_task`, `update_task`（依赖管理并入：`add_depends_on` / `remove_depends_on`）, `delete_task`
- 图表统计：`get_project_stats`（`kind` ∈ `overview` / `burndown` / `gantt` / `devlog`，多合一）

### 5.3 开发记录与状态会话（7 个）

- 开发记录录入：`log_dev_entry`（`entry_type` ∈ progress/difficulty/todo/decision/blocker/note，六合一）
- 开发会话维护：`start_dev_session`, `end_dev_session`
- 记录查询与维护：`list_dev_logs`, `manage_dev_log`（`action` ∈ `update` / `resolve` / `delete`，三合一）
- 状态与报告聚合：`get_project_state`, `get_dev_report`
- （记录统计并入 `get_project_stats(kind="devlog")`）

### 5.4 任务评论（2 个）

- `add_comment`, `list_comments`（删除评论走前端 UI 或 REST `DELETE /api/comments/{id}`）

## 6. 外部 Agent 的指令配置（Rule / Prompt 模板）

为防止外部模型（特别是轻量模型）在缺少指引时盲目操作，建议在项目的 **`.cursorrules`**、**`CLAUDE.md`** 或 **Agent System Prompt** 中粘贴以下规则：

````markdown
### HPF Work Manager 外部 Agent 行为协议
1. 【启动首检】：每次开工前，先调用 `get_manager_status()` 获取驱动模式与指南。
2. 【任务决策】：
   - 询问下一步任务时优先调用 `get_next_steps(project_name)`。
   - 自主提报新任务时，必须调用 `propose_task_plan(project_name, tasks=[...], auto_create=True)`，严禁凭空想象不存在的架构。
3. 【过程留痕】：开发中产生技术方案选型调用 `log_decision`，遇到卡点调用 `log_difficulty`。
4. 【结项核销】：功能开发完成后，严禁直接调用 `update_task(status="done")`！
   必须调用 `verify_and_complete_task(task_id, git_ref, verification_evidence)`，填入真实 Git Commit 与测试证据。
````

## 7. 连通性排错指南

| 常见问题 | 排查要点 |
|---|---|
| **400 Invalid Host** | 请求 Header 中的 Host 未在 `MCP_ALLOWED_HOSTS` 白名单中。直接使用 Tailscale IP `100.69.225.112` 访问即可免除 Host 限制。 |
| **401 Unauthorized** | 提供了过期的 API Key。在 Tailscale/Localhost 网络下，建议直接**移除 Authorization Header** 走内网免鉴权模式。 |
| **SSE 流断连 / 卡顿** | Nginx 反向代理未配置 `proxy_buffering off;`。若自行部署反代，请确保关闭代理缓冲与分块传输缓存。 |
| **502 Bad Gateway** | 后端 Docker 服务尚未启动完成。使用 `docker ps` 确认 `hpf-work-manager-backend-1` 状态处于 `healthy`。 |
