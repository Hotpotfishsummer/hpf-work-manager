# 08 · AI 接入指南

> 让 Claude Code / Cursor / 自研 agent 等 AI 编码工具，在编码过程中自动更新任务、项目进度
> 与开发记录（DevLog），并通过 MCP + SSE 实现多工具、多机器的实时进度同步。

## 1. 概览

系统为 AI 工具提供两条接入路径：

| 路径 | 适用场景 | 前置 |
|---|---|---|
| **MCP Server**（推荐） | 支持 MCP 的编码工具（Claude Code、Cursor 等） | 配置一个 MCP server 地址 |
| **REST API + API Key** | 脚本 / 不支持 MCP 的工具 | 用 `/api/keys/exchange` 换 JWT |

两条路径共享同一套业务逻辑与数据，AI 工具的任何更新（任务、项目、DevLog、会话）都会通过 **SSE** 实时推送到前端页面。

系统与 git 是**一体两面**：git 记录"代码状态"，DevLog 记录"开发过程"（为什么、卡在哪、下一步）。DevLog 只存 `git_ref` 引用，不解析 git。

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  Vue 前端    │   │  AI 工具     │   │  AI 工具     │
│ (浏览器)     │   │  (MCP client)│   │  (HTTP/REST)│
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │                 │                 │
       ▼                 ▼                 ▼
┌───────────────────────────────────────────────┐
│          FastAPI（backend:8000）              │
│  REST  │  API-Key  │  MCP Server  │  SSE 推送 │
└──────────────────────┬────────────────────────┘
                       ▼
                PostgreSQL
```

## 2. 准备：创建 API Key

1. 登录 Web 前端 → 「API Keys」→ 「新建 Key」。
2. 输入名称（如 `Claude Code`），点击生成。
3. **立即复制保存** `hpf_..._...` 完整串 —— 仅显示一次。

> 安全提示：API Key 丢失后无法找回，请直接在页面上撤销并重建。

## 3. 方式一：MCP Server 接入（推荐）

### 3.1 获取 MCP 端点地址

部署后，MCP 端点即为：

```
https://<你的域名>/mcp
```

- 与前端同源（nginx 已反代 `/mcp`）。
- 需要 HTTPS（生产环境务必配置，见 `05-部署指南.md`）。

### 3.2 配置示例

**Claude Code**（`.mcp.json` 或 `claude mcp add`）：

```json
{
  "mcpServers": {
    "hpf-work-manager": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer hpf_a1b2c3_<你的API Key>"
      }
    }
  }
}
```

**Cursor**（Settings → MCP Servers → Add）：

```
Type:        HTTP
URL:         https://example.com/mcp
Header:      Authorization: Bearer hpf_a1b2c3_<你的API Key>
```

> 不同工具配置入口不同，本质都是指定 `url` + `Authorization` 头。key 也可换成登录后获得的 JWT。

### 3.3 可用工具

**项目 / 里程碑 / 任务**

| 工具 | 说明 |
|---|---|
| `list_projects` / `get_project` | 查询项目 |
| `create_project` / `update_project` / `delete_project` | 项目增删改 |
| `list_milestones` / `create_milestone` / `update_milestone` / `delete_milestone` | 里程碑管理 |
| `list_tasks` / `get_task` | 查询任务（可按 `status`/`overdue`/`search` 过滤，offset/limit 分页） |
| `create_task` / `update_task` / `delete_task` | 任务增删改 |
| `add_task_dependency` / `remove_task_dependency` | 任务依赖管理 |
| `get_project_stats_mcp` / `get_burndown_mcp` / `get_gantt_mcp` | 进度/燃尽/甘特图数据 |

**开发记录（DevLog / 会话）**

| 工具 | 说明 |
|---|---|
| `log_progress` / `log_difficulty` / `log_todo` / `log_decision` / `log_blocker` / `log_note` | 写入一条开发记录 |
| `start_dev_session` / `end_dev_session` | 开发会话开始 / 收口 |
| `list_dev_logs` | 查询记录（按 `entry_type`/`status`/`since` 过滤，offset/limit 分页） |
| `list_task_dependencies` | 列出任务前置依赖（含名称/状态，判断可否开工） |
| `get_dev_log_stats_mcp` | 开发记录统计（今日/难点/待办/阻塞/决策） |
| `get_project_state` | 上下文聚合包：一次拉取待办/难点/阻塞/最近进展/进行中会话 |
| `get_dev_report` | 生成阶段开发汇报（Markdown） |
| `update_dev_log` / `delete_dev_log` / `resolve_dev_log` | 记录维护（`resolve` 仅 todo/blocker） |

### 3.4 开发记录（DevLog）协议

> DevLog 是**过程叙事**（任务/里程碑管结果，记录管过程）。每次会话建议遵循以下流程：

```
1. 开始会话：start_dev_session(project_id, title)  —— 后续 log_* 自动归入该会话
2. 过程中随手写：
   - 完成一件值得记录的事 → log_progress
   - 卡住 / 绕过的坑       → log_difficulty
   - 下一步要做的事       → log_todo
   - 拍板的技术方案及理由 → log_decision
   - 无法推进的阻塞项     → log_blocker
3. 结束时收口：end_dev_session(session_id, summary)
4. 新会话开始前，先 get_project_state(project_id) 恢复上下文
```

**条目约束**：

- `entry_type` ∈ `progress/difficulty/todo/decision/blocker/milestone/note`
- `severity`（low/medium/high）仅用于 `difficulty` / `blocker`
- `status`（open/done）仅用于 `todo` / `blocker`；`resolve_dev_log` 仅对这两类生效
- `related_task_ids` 必须是**本项目内**的任务，否则拒绝
- `git_ref` 建议填 commit 或分支名，仅作引用溯源（系统不解析 git）

**示例**：一次会话的完整写法

```
start_dev_session(project_id=1, title="实现登录模块")
log_progress(project_id=1, title="完成 JWT 签发与校验", git_ref="a1b2c3d")
log_difficulty(project_id=1, title="异步客户端挂起", severity="high",
               content="httpx 未用 async with 导致连接泄漏")
log_todo(project_id=1, title="补充登录接口的单元测试")
log_decision(project_id=1, title="选用 SQLAlchemy 2.0 异步",
             content="与现有 FastAPI 生态一致，避免双 ORM")
end_dev_session(session_id=3, summary="完成认证流程与 12 个单测")
```

### 3.5 状态机约定

AI 工具更新任务时，系统自动维护派生字段：

- `status="done"` → 自动 `progress=100` 并盖章 `completed_at`
- `status` 改为非 `done` → 自动清空 `completed_at`
- `status="done"` 时忽略 `progress` 写入（钳制在 0-100）

**示例**：完成任务

```
update_task(task_id=42, status="done")
# => progress 自动变为 100，completed_at 自动盖章
```

## 4. 方式二：REST API + API Key（脚本 / 非 MCP 工具）

```bash
# 1. 用 API Key 换取 JWT
curl -X POST https://example.com/api/keys/exchange \
  -H "Content-Type: application/json" \
  -d '{"key": "hpf_a1b2c3_<你的API Key>"}'
# => { "access_token": "<jwt>" }

# 2. 用 JWT 调用既有 REST 接口
curl https://example.com/api/projects/1/tasks \
  -H "Authorization: Bearer <jwt>"
```

完整 REST 端点见 `03-API参考.md`。

## 5. 实时同步（SSE）

AI 工具每次写操作后，后端会向该项目的所有 SSE 订阅者广播事件：

```http
GET /api/events/stream?project_id=1
Authorization: Bearer <jwt 或 API Key>
```

事件示例：

```
event: project-update
data: {"type":"updated","entity":"task","entity_id":42,"project_id":1,"ts":"2026-08-12T05:41:00+00:00"}
```

- 前端项目详情 / 看板 / 甘特图 / **开发记录** 页面已自动订阅，收到事件后自动刷新。
- 多台机器上的多个工具，只要连接同一服务，进度即实时一致 —— 不再依赖文档与 git 手动同步。

## 6. 权限与安全

- **API Key 无过期**，可随时在页面撤销；建议每工具一个 key，便于审计与回收。
- 所有写操作都走**完整 CRUD** 权限（AI 可创建/修改/删除），请仅向可信工具发放 key。
- MCP 端点启用 **DNS 防重绑定**保护，仅允许配置的 Host（`MCP_ALLOWED_HOSTS`，默认从 `CORS_ORIGINS` 推导）。
- 生产环境务必通过 HTTPS 访问（见 `05-部署指南.md`），避免 key 明文传输。

## 7. 环境变量参考

| 变量 | 默认 | 说明 |
|---|---|---|
| `MCP_ENABLED` | `true` | 是否启用 MCP 端点 |
| `MCP_PATH` | `/mcp` | MCP 端点路径 |
| `MCP_ALLOWED_HOSTS` | 空 | MCP 允许的 Host（逗号分隔），留空则从 CORS_ORIGINS 推导 |
