# 06 · 开发指南

> 面向开发者：环境搭建、测试、代码约定、扩展路线

## 1. 环境搭建

### 1.1 后端（Python 3.12+）

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e .                # 安装全部依赖（依赖锁定见 pyproject.toml）
cp .env.example .env
```

本地无 PostgreSQL 时，可用 Docker 只起数据库：

```bash
docker compose up -d postgres   # 仅启动数据库容器
```

### 1.2 前端（Node 18+）

```bash
cd frontend
npm install
npm run dev
```

> `sass-embedded` 为 frappe-gantt SCSS 所需，已在 devDependencies。

## 2. 测试与质量

### pytest 测试套件（首选，113+ 用例）

```bash
cd backend && .venv/bin/python -m pytest -q
```

- SQLite 内存库，无需 PostgreSQL；conftest 自带 `ENVIRONMENT=test` 注入，无 `.env` 也能跑
- 覆盖：注册/登录/401、API Key、项目/里程碑/任务 CRUD、依赖管理、分页与搜索排序、
  422/400/401/404 错误形状、枚举校验、MCP 全链路（认证/initialize/工具调用）、
  `/overview` 聚合统计、SSE 鉴权
- 关键约定（`pyproject.toml`）：`asyncio_default_test_loop_scope = "session"`——
  全套共享会话级事件循环，否则会话级 MCP 会话管理器（anyio task group）会跨循环挂死

### Lint（ruff）

```bash
cd backend && .venv/bin/ruff check .
```

- 规则集见 `pyproject.toml [tool.ruff.lint]`：E4/E7/E9/F/I/B/UP/RUF
- `alembic/versions` 生成代码已排除；B008（FastAPI `Depends()` 惯用法）、
  RUF001-003（中文全角标点）、UP046 已 ignore
- 模型文件关系注解用 `TYPE_CHECKING` 导入，勿删

### 端到端 API 验证（`scripts/e2e_check.py`，辅助）

```bash
python scripts/e2e_check.py
```

- `/tmp` 独立 SQLite 临时库，41 项断言：注册/登录/Key 兑换/CRUD/状态机/燃尽/甘特/SSE

### 数据库迁移验证

```bash
cd backend && alembic upgrade head --sql   # 离线生成 SQL 供审查/CI
```

### 前端构建验证

```bash
cd frontend && npm run build    # vue-tsc 类型检查 + vite 生产构建
```

### CI（GitHub Actions）

`.github/workflows/ci.yml`：push/PR 到 main 自动跑——后端 ruff + pytest + alembic
离线校验（Python 3.12），前端 vue-tsc + 构建 + 产物 ≤5MB 红线（Node 22）。
CI 无 `.env`，敏感检查依赖显式注入的环境变量（见 pytest 步骤 env）。

## 3. 常用开发流程

### 新增 API 端点

1. `app/schemas/` 定义请求/响应 Pydantic 模型（复用 `BaseModel`，`from_attributes=True`）
2. `app/routers/` 新增路由函数，注入 `CurrentUser` / `DbDep`（见 `deps.py`）
3. 在 `app/main.py` 注册 router（`prefix="/api"`）
4. 前端 `src/api/index.ts` 增加调用（带 TS 泛型），`src/types/index.ts` 对齐类型
5. 跑 e2e 与前端 build 验证

### 修改数据模型

1. 改 `app/models/*.py`
2. `cd backend && alembic revision --autogenerate -m "描述"`（需连接数据库）
3. 审查生成的迁移文件后 `alembic upgrade head`
4. 同步 `docs/02-数据模型.md`

### 新增页面

1. `src/views/` 新建视图；`src/router/index.ts` 注册路由
2. 组件样式引用 `design/tokens.css` 变量（**禁内联 hex**）
3. UI 改动前重读根目录 `DESIGN.md`，遵循 `--md-*` token（Apple × MD3）

## 4. 代码约定

### 后端
- 类型注解完整（`Mapped[]`、`| None`、`Annotated` 依赖注入）
- 路由层薄、业务逻辑放 `services/`（如进度/燃尽图计算）
- 统一 UTC 时间（`utils/time.py`）；日期用 `date`，时间戳用带时区 `datetime`
- 所有权校验：跨表资源查询一律 `JOIN Project` 过滤 `owner_id`
- 版本锁定：`passlib[bcrypt]==1.7.4` + `bcrypt==4.0.1`（勿升级 bcrypt）

### 前端
- 组件 `<script setup lang="ts">` 组合式 API
- API 调用统一走 `src/api/`（拦截器已处理 JWT 与错误提示）
- 状态色映射固定：done→success / 进行中→primary / 待办→on-surface-variant / **延期→error 红**
- 提交前跑 `npm run build`（含类型检查）

### Git
- 提交信息：`feat:` / `fix:` / `docs:` / `chore:` 前缀 + 中文描述
- 忽略项已由根 `.gitignore` 管理（node_modules/dist/pycache/.env/*.db/.workbuddy）

## 6. 常见问题

**Q：`vite build` 报 `sass-embedded` not found？**
A：`npm install -D sass-embedded`（frappe-gantt 的 SCSS 依赖）。

**Q：注册提示"用户名或邮箱已被注册"但数据库是新的？**
A：检查是否复用了旧 SQLite 文件（历史 e2e 残留）。测试脚本已改用 /tmp 独立文件，勿在项目根创建 `*.db` 测试库。

**Q：JWT 提示 `InsecureKeyLengthWarning`？**
A：`SECRET_KEY` 过短（<32 字节）。生产用 `secrets.token_hex(32)` 生成。

**Q：`alembic upgrade head --sql` 是干什么的？**
A：离线生成迁移 SQL（不连数据库），用于审查/CI 校验迁移正确性。
