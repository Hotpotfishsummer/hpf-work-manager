# 01 · 架构设计

> 适用版本：`v0.1.0`（初始提交 `e1c2a44`）

## 1. 项目概述

**HPF Work Manager** 是一个面向个人/小团队的任务、项目管理与进度追踪 Web 应用。

- **形态**：前后端分离（SPA + REST API）
- **部署**：全容器化，Docker Compose 一键编排（前端 / 后端 / 数据库三容器）
- **UI 风格**：Apple × Material Design 3 设计系统（设计源：根目录 `DESIGN.md`，浅色/深色双主题）

## 2. 技术栈决策

| 层 | 选型 | 决策理由 |
|---|---|---|
| 前端框架 | Vue 3.5 + Vite 6 + TypeScript 5 | 组合式 API 生态成熟，TS 保证前后端类型对齐 |
| 状态管理 | Pinia | Vue 官方推荐，轻量、类型友好 |
| UI 组件库 | Element Plus | 后台场景组件齐全、中文文档完善 |
| 甘特图 | frappe-gantt（MIT） | **避开 GPL 的 dhtmlx-gantt**；轻量 ~60KB，需自封装 Vue 组件 |
| 图表 | ECharts 5（Apache 2.0） | 燃尽图等统计图表 |
| 后端框架 | FastAPI + Uvicorn | 异步高性能、自动 OpenAPI 文档、Pydantic 校验 |
| ORM | SQLAlchemy 2.0（async）+ asyncpg | 原生异步驱动，类型化 ORM 风格 |
| 迁移 | Alembic | SQLAlchemy 官方迁移工具 |
| 认证 | PyJWT + passlib[bcrypt] | JWT 无状态认证；**python-jose 已停维护，不用** |
| 数据库 | PostgreSQL 16 | JSONB/全文检索扩展空间，生产主流 |
| 容器编排 | Docker Compose | 单机多容器一键编排，满足个人/小团队 |

### 版本锚点（防兼容坑）

```toml
passlib[bcrypt]==1.7.4
bcrypt==4.0.1        # passlib 与 bcrypt>=4.1 不兼容，必须锁定
```

前端另需 `sass-embedded`（devDependency）：frappe-gantt 的 SCSS 需要预处理器，否则 `vite build` 失败。

## 3. 系统架构

```
┌─────────────────────────────┐
│  浏览器 (SPA)                │
│  Vue3 + Element Plus        │
└──────────────┬──────────────┘
               │ HTTP (REST JSON)
               ▼
┌─────────────────────────────┐        ┌──────────────────┐
│ frontend 容器               │        │ 开发模式          │
│ nginx:alpine                │───────▶│ vite dev server   │
│ · 静态资源 / SPA 回退        │  /api/ │ (proxy → backend) │
│ · /api 反向代理 → backend    │        └──────────────────┘
└──────────────┬──────────────┘
               │ proxy_pass http://backend:8000
               ▼
┌─────────────────────────────┐
│ backend 容器                │
│ python:3.12-slim            │
│ FastAPI + SQLAlchemy async  │
│ 启动: alembic upgrade head  │
│        && uvicorn :8000     │
└──────────────┬──────────────┘
               │ postgresql+asyncpg://
               ▼
┌─────────────────────────────┐
│ postgres 容器               │
│ postgres:16-alpine          │
│ 数据卷: pgdata（持久化）      │
└─────────────────────────────┘
```

**关键链路**：

1. 用户经 nginx（`:8080`）访问 SPA；`/api/*` 同源反代到后端，**生产无 CORS 问题**
2. 后端启动先执行 `alembic upgrade head` 建表，再起 Uvicorn
3. 业务数据全部带 `owner_id`，按当前登录用户隔离
4. `depends_on + healthcheck` 保证 postgres 就绪后 backend 才启动

## 5. 核心设计决策

### 5.1 进度算法
- **项目进度 = 已完成任务数 / 总任务数 × 100**（实时计算，不落库）
- `Task.estimated_hours` 字段已预留，未来可扩展工时加权模式（本次不做 UI）

### 5.2 延期判定
- 后端派生计算：`status != 'done' AND due_date < today(UTC)`，**不落库**
- 前端三处高亮：项目概览（延期列表）、任务看板（卡片红边 + 标签）、甘特图（条形标红）

### 5.3 燃尽图（轻量方案）
- **无快照表**：期望线 = 项目起止日内从总任务数线性降到 0；实际线 = 基于 `Task.completed_at` 按日累计推导
- 历史审计如需快照，未来可加 ProgressLog 表（本次不做）

### 5.4 状态流转规则（后端强制）
| 操作 | 规则 |
|---|---|
| `status → done` | 强制 `progress = 100`，写 `completed_at = now()` |
| `status → 非 done` | 清空 `completed_at` |
| 直接改 `progress` 且非 done | 正常更新（0-100 收敛） |
| 完成任务 | 批量/单任务均遵守上述规则 |

### 5.5 认证与数据隔离
- JWT 有效期 7 天（`ACCESS_TOKEN_EXPIRE_MINUTES`），**无 refresh token**（个人场景）
- 依赖链：`OAuth2PasswordBearer` → `get_current_user` → 路由注入 `CurrentUser`
- **API Key**：长期有效、可撤销的机器凭证（`core/apikey.py`，HMAC 哈希存储，创建时只展示一次）。可经 `/api/keys/exchange` 换 JWT 调 REST；MCP 端点直接接受 API Key/JWT
- 所有业务表 `owner_id` 隔离；跨表访问（任务/里程碑）经 `JOIN Project` 校验归属

### 5.7 AI 工具接入（MCP + API Key + SSE）
- **MCP Server**（`mcp_server.py`）：Streamable HTTP 传输，34 个工具覆盖项目/里程碑/任务/依赖/统计/开发记录；复用 REST 的 services 层，避免逻辑分叉
  - 认证：`mcp_auth.py` 中间件，Bearer 解析 API Key/JWT，经 contextvar 传给工具处理器
  - 生命周期：宿主 App lifespan 启动 MCP 会话管理器（挂载子应用不会自动触发其 lifespan）
  - DNS 防重绑定：`MCP_ALLOWED_HOSTS`（默认从 `CORS_ORIGINS` 推导）
- **SSE 实时推送**（`core/events.py` + `routers/events.py`）：进程内按项目维度的广播；写操作后 `publish()`，前端 `useProjectEvents` 订阅刷新
- 状态机抽取到 `services/tasks.py`，REST 与 MCP 复用（`apply_task_update`/`to_out`）

### 5.6 时区
- 后端统一存 UTC（`datetime.now(timezone.utc)`），日期字段用 `Date` 类型
- 前端按本地时区展示

## 6. 非功能性设计

| 维度 | 措施 |
|---|---|
| 数据库连接 | 连接池 `pool_size=5, max_overflow=5, pool_pre_ping=True` |
| 启动顺序 | postgres `pg_isready` healthcheck + `depends_on: condition: service_healthy` |
| 迁移并发 | 由 backend 容器启动时单实例执行迁移 |
| 镜像体积 | 前后端均多阶段构建，运行层剥离构建依赖 |
| CORS | 生产 nginx 同源反代；dev vite proxy；`CORS_ORIGINS` 白名单兜底 |
| 安全 | 密码 bcrypt 哈希；`.env` 不入库；容器非 root 用户运行 |
