# 05 · 部署指南

## 1. 前置要求

- Docker Engine 24+ 与 Docker Compose v2（Docker Desktop 即可）
- 预留端口：`8080`（前端，可通过 `FRONTEND_PORT` 修改）、`8000`（后端，开发模式）

## 2. 环境变量

复制模板并按需修改：

```bash
cp .env.example .env
```

| 变量 | 默认值 | 说明 |
|---|---|---|
| `POSTGRES_USER` | `hpf` | 数据库用户 |
| `POSTGRES_PASSWORD` | `hpf` | **生产必改** |
| `POSTGRES_DB` | `hpf_work` | 数据库名 |
| `SECRET_KEY` | `change-me-in-production` | **生产必改**。生成：`python -c "import secrets; print(secrets.token_hex(32))"` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `10080` | JWT 有效期（7 天） |
| `CORS_ORIGINS` | `http://localhost:8080` | 逗号分隔白名单（生产走同源反代，通常无需改） |
| `FRONTEND_PORT` | `8080` | 前端对外端口 |
| `MCP_ENABLED` | `true` | 是否启用 MCP Server 端点（AI 工具接入） |
| `MCP_PATH` | `/mcp` | MCP 端点路径 |
| `MCP_ALLOWED_HOSTS` | 空 | MCP 允许的 Host（逗号分隔）；空则从 `CORS_ORIGINS` 推导 |

> 注意：`.env` 已加入 `.gitignore`，不会提交版本库。

## 3. 生产部署

```bash
docker compose up -d --build
```

启动顺序（由 compose 保证）：

1. `postgres` 启动并通过 `pg_isready` healthcheck
2. `backend` 构建并启动：先 `alembic upgrade head` 建表，再起 Uvicorn（:8000，仅内网）
3. `frontend` 构建（node 构建静态文件 → nginx）并对外服务（:8080）

访问：`http://localhost:8080`

### 常用运维命令

```bash
docker compose ps                # 查看状态
docker compose logs -f backend   # 后端日志
docker compose logs -f frontend  # 前端/nginx 日志
docker compose down              # 停止（数据保留在 pgdata 卷）
docker compose down -v           # 停止并删除数据卷（⚠️ 清空数据）
docker compose up -d --build     # 更新代码后重新构建部署
```

### 数据持久化

- PostgreSQL 数据保存在命名卷 `pgdata`，容器重建不丢失
- 升级/迁移自动执行（backend 启动时 `alembic upgrade head`）

## 4. 开发模式（热更新）

```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml up --build
```

override 的行为：

| 服务 | 行为 |
|---|---|
| backend | 源码卷挂载 `./backend:/app`，`uvicorn --reload` 热重载；暴露 `:8000` |
| frontend | 复用 Dockerfile 的 node 构建阶段跑 `npm run dev`（Vite :8080，proxy `/api` → backend:8000） |
| postgres | 同生产 |

> 前端容器内 `node_modules` 由匿名卷保护，宿主机源码改动实时生效。

## 5. nginx 配置说明（`frontend/nginx.conf`）

```nginx
location / {                    # SPA 路由回退
    try_files $uri $uri/ /index.html;
}
location /api/ {                # 反向代理到后端（含 SSE：关闭缓冲）
    proxy_pass http://backend:8000;
    proxy_buffering off;        # SSE 实时推送必需
}
location /mcp {                 # MCP Server（AI 工具接入，Streamable HTTP）
    proxy_pass http://backend:8000;
    proxy_buffering off;        # MCP 也走 SSE 流
}
location /assets/ {             # 静态资源 7 天缓存
    expires 7d;
}
```

- 同源反代使生产环境**无 CORS 问题**
- `backend` 容器名由 compose 服务名解析
- `/api/` 与 `/mcp` 均关闭缓冲，保证 SSE/MCP 事件实时推送

## 5.1 生产 HTTPS（AI 工具接入必配）

AI 工具通过 `https://<域名>/mcp` 与 `/api/...` 接入。生产环境务必配置 HTTPS，
避免 API Key 明文传输。推荐在 nginx 前端容器前加一层 TLS 反代（Caddy / nginx / 云负载均衡 + 证书）：

```bash
# Caddy 简易示例（最省事，自动获取 Let's Encrypt 证书）
# Caddyfile：
#   work.example.com {
#       reverse_proxy localhost:8080
#   }
```

- 证书可改用云厂商负载均衡 + ALB 证书，或自建 nginx + certbot。
- 配置后，MCP 端点地址为 `https://work.example.com/mcp`，AI 工具用此地址 + API Key 连接。

## 6. 本地开发（不使用 Docker）

### 后端

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e .
cp .env.example .env            # 按需修改 DATABASE_URL
alembic upgrade head            # 建表
uvicorn app.main:app --reload --port 8000
```

### 前端

```bash
cd frontend
npm install
npm run dev                     # http://localhost:8080（proxy /api → :8000）
```

## 7. 排障

| 症状 | 排查 |
|---|---|
| 前端 502 Bad Gateway | backend 未就绪：`docker compose logs backend`；确认 postgres healthcheck 通过 |
| 表不存在/迁移报错 | backend 启动日志看 `alembic upgrade head`；手动进容器执行 `alembic current` |
| 登录后 401 | 时间不同步导致 JWT 校验失败（容器与宿主时钟）；重启容器 |
| 端口被占用 | 修改 `.env` 的 `FRONTEND_PORT`；dev 模式改 `docker-compose.override.yml` 端口 |
| 数据库连不上 | `docker compose up -d postgres` 后重试；`docker compose logs postgres` |
| 密码报错 bcrypt 兼容 | 确认锁定 `passlib[bcrypt]==1.7.4` + `bcrypt==4.0.1`（见 pyproject.toml） |
