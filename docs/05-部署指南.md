## 1. 部署架构一览

本应用为前后端分离，生产编排由三个容器组成一个桥接网络：

```
┌──────────────────────────────────────────────────────────────┐
│  宿主机                                                       │
│                                                               │
│   [ 可选前置反代 :443 HTTPS ]  ← Caddy / Nginx+certbot        │
│            │ 转发 /、/api/、/mcp                              │
│            ▼                                                  │
│   frontend (nginx :80)  →  对外 FRONTEND_PORT(默认 8080)      │
│       │  /api/ 与 /mcp 同源反代                               │
│       ▼                                                      │
│   backend  (uvicorn :8000，仅内网，不暴露宿主机端口)          │
│       │  SQLAlchemy asyncpg                                  │
│       ▼                                                      │
│   postgres (:5432，仅内网)  ← 数据卷 pgdata 持久化           │
└──────────────────────────────────────────────────────────────┘
```

| 服务 | 镜像 | 端口 | 对外 | 说明 |
|---|---|---|---|---|
| `postgres` | postgres:16-alpine | 5432 | 否 | 数据落在命名卷 `pgdata`，容器重建不丢 |
| `backend` | 本地构建 | 8000 | 否 | 启动先 `alembic upgrade head` 建表/迁移，再起 Uvicorn |
| `frontend` | 本地构建（nginx） | 80 → `FRONTEND_PORT` | 是 | 静态资源 + 同源反代 `/api/`、`/mcp` |

- 启动顺序由 Compose 保证：`postgres` 通过 `pg_isready` 健康检查 → `backend` 依赖其就绪 → `frontend` 依赖 `backend`。
- 浏览器只访问 `frontend`（`http://<IP>:8080` 或经前置 HTTPS 反代）。`backend` 与 `postgres` 不暴露到公网，更安全。
- 生产默认**不暴露后端 8000 端口**；MCP 端点统一走前端反代后的 `/mcp`。

## 2. 前置准备

### 2.1 服务器 / 环境

- 推荐 **Ubuntu 22.04 / 24.04 LTS** 或其他现代 Linux。
- 最低配置：2 vCPU / 2 GB 内存（PostgreSQL 建议留 1 GB 以上）。
- 需开放防火墙端口：
  - `22`（SSH，必备）
  - 若用前置 HTTPS 反代：`80`、`443`（证书申请与访问）
  - 若**不用**前置反代、直接以 `:8080` 对外：`8080`
  - `8000` **不要**对公网开放（后端密钥/接口暴露风险）

### 2.2 安装 Docker Engine + Compose v2

**方式一：官方一键脚本（最省事）**

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # 当前用户免 sudo 跑 docker（需重登录生效）
sudo systemctl enable --now docker
```

**方式二：Ubuntu apt**

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-plugin
sudo usermod -aG docker $USER
sudo systemctl enable --now docker
```

验证安装：

```bash
docker --version
docker compose version          # 注意 v2 是 `docker compose`（无连字符），v1 才用 docker-compose
```

### 2.3 获取代码

```bash
# 方式一：git 克隆（便于后续更新）
git clone <你的仓库地址> hpf-work-manager
cd hpf-work-manager

# 方式二：下载 Release 压缩包后解压
# unzip hpf-work-manager-vX.Y.Z.zip && cd hpf-work-manager
```

确认目录内含 `docker-compose.yml`、`docker-compose.override.yml`、`backend/`、`frontend/`、`.env.example`。

## 3. 第一次部署（逐步）

### 3.1 配置环境变量 `.env`

复制模板并编辑：

```bash
cp .env.example .env
nano .env            # 或 vim / code
```

> `.env` 已被 `.gitignore` 忽略，不会提交到版本库。生产务必改掉默认密钥与密码。

#### 全部变量说明

| 变量 | 默认值 | 生产建议 |
|---|---|---|
| `POSTGRES_USER` | `hpf` | 可保留 |
| `POSTGRES_PASSWORD` | `hpf` | **必改**为强随机密码 |
| `POSTGRES_DB` | `hpf_work` | 可保留 |
| `SECRET_KEY` | `change-me-in-production` | **必改**；JWT 签名密钥，泄露可伪造 token |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `10080` | JWT 有效期（默认 7 天），一般不用改 |
| `CORS_ORIGINS` | `http://localhost:8080` | 见下方"域名规划" |
| `MCP_ENABLED` | `true` | 是否启用 MCP 端点 |
| `MCP_PATH` | `/mcp` | MCP 端点路径 |
| `MCP_ALLOWED_HOSTS` | 空 | 见下方"域名规划" |
| `FRONTEND_PORT` | `8080` | 前端对外端口 |

**生成强密钥**：

```bash
# 用 openssl 生成 32 字节十六进制（或 python -c "import secrets; print(secrets.token_hex(32))"）
openssl rand -hex 32
```

把输出填到 `SECRET_KEY=`。数据库密码同理用强随机串：

```bash
openssl rand -base64 18
```

#### 域名规划（影响 CORS 与 MCP 防盗链）

若你打算用域名 + HTTPS 反代（推荐，AI 工具 MCP 接入必需）：

- `CORS_ORIGINS=https://work.example.com`（浏览器访问的对外域名，逗号分隔可多个）
- `MCP_ALLOWED_HOSTS=work.example.com`（MCP DNS 防重绑定允许的 Host，留空则从 `CORS_ORIGINS` 推导）

若只是本机/内网直接以 `:8080` 使用、不做 HTTPS 反代：

- `CORS_ORIGINS=http://localhost:8080`（或你的服务器 IP，如 `http://192.168.1.10:8080`）
- `MCP_ALLOWED_HOSTS=` 留空即可

> 改完 `.env` 后，**必须重建** `backend`/`frontend` 容器才会生效（见第 5、6 节）。

### 3.2 启动

> ⚠️ **生产只用基础编排文件**：根目录的 `docker-compose.override.yml` 是**开发热更新**配置（挂载源码、`npm run dev`、暴露后端 8000 端口）。`docker compose` 默认会**自动合并**它，导致生产环境跑成开发模式、并占用 8080 端口。请**始终显式加 `-f docker-compose.yml`**，不要依赖默认合并。

```bash
docker compose -f docker-compose.yml up -d --build
```

- 首次会构建 `backend`、`frontend` 两个镜像，耗时几分钟（取决于网络与机器）。
- 日志实时滚动；看到 `frontend` 启动后 `Ctrl-C` 不影响（已 `-d` 后台运行）。

### 3.3 验证

```bash
docker compose ps                 # 三个服务 State 应为 running/healthy
docker compose logs -f backend    # 关注启动日志里 alembic 迁移是否成功
```

健康检查：

```bash
curl http://localhost:8080/api/health
# → {"status":"ok"}
```

浏览器访问：

```
http://<服务器IP>:8080
```

### 3.4 创建首个账号

- 系统**开放注册**（无独立 admin 角色）。打开页面 → 注册第一个用户，该用户即为自己项目的 owner。
- 注册后在「**API Keys**」页新建一个 Key，复制保存——这是后续让 AI 编码工具（Claude Code / Cursor 等）通过 MCP 自动同步进度的凭证（详见 [`08-AI接入指南`](./08-AI接入指南.md)）。

## 4. 生产 HTTPS 反代（AI 工具 MCP 接入必配）

AI 工具通过 `https://<域名>/mcp` 与 `/api/...` 接入，**生产环境务必配置 HTTPS**，避免 API Key 明文传输、规避 MCP 的 DNS 防重绑定拦截。

> 以下两种方案选其一。配置完反代后，记得回 3.1 调整 `CORS_ORIGINS` 与 `MCP_ALLOWED_HOSTS` 为对外域名，再 `docker compose -f docker-compose.yml restart backend frontend`。

### 4.1 方案 A：Caddy（最简，自动证书）

Caddy 默认自动申请并续期 Let's Encrypt 证书，最适合个人/小团队。

安装（Ubuntu）：

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

Caddyfile（`/etc/caddy/Caddyfile`）：

```
work.example.com {
    reverse_proxy localhost:8080
}
```

启动并开机自启：

```bash
sudo systemctl enable --now caddy
```

Caddy 会自动监听 80/443、申请证书。随后设置 `.env`：

```
CORS_ORIGINS=https://work.example.com
MCP_ALLOWED_HOSTS=work.example.com
```

```bash
docker compose -f docker-compose.yml restart backend frontend
```

MCP 端点地址即：`https://work.example.com/mcp`

### 4.2 方案 B：Nginx + certbot

安装：

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

反代配置 `/etc/nginx/sites-available/hpf`：

```nginx
server {
    listen 80;
    server_name work.example.com;

    # 证书申请期间先放通，certbot 会自动加 443 与跳转
    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用站点并申请证书：

```bash
sudo ln -s /etc/nginx/sites-available/hpf /etc/nginx/sites-enabled/hpf
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d work.example.com        # 自动改配置 + 定时续期
```

certbot 会在 443 上补全 `/api/`、`/mcp` 的同源反代与 SSE 关闭缓冲（若需精细控制，可手动补充，参考 `frontend/nginx.conf` 的 `/api/`、`/mcp` 段：`proxy_buffering off;` 等）。同样设置 `.env` 的 `CORS_ORIGINS`/`MCP_ALLOWED_HOSTS` 后 `docker compose -f docker-compose.yml restart backend frontend`。

### 4.3 验证 MCP over HTTPS

在 AI 工具侧配置（以 Claude Code 为例，详见 [`08-AI接入指南`](./08-AI接入指南.md)）：

```json
{
  "mcpServers": {
    "hpf-work-manager": {
      "type": "http",
      "url": "https://work.example.com/mcp",
      "headers": { "Authorization": "Bearer hpf_a1b2c3_<你的API Key>" }
    }
  }
}
```

## 5. 日常运维

```bash
docker compose ps                # 查看三个服务状态
docker compose logs -f backend   # 后端日志（含每次 alembic 迁移记录）
docker compose logs -f frontend  # nginx 访问/错误日志
docker compose -f docker-compose.yml restart           # 重启所有服务（不重建镜像）
docker compose down              # 停止（数据卷 pgdata 保留）
docker compose down -v           # 停止并删除数据卷（⚠️ 清空所有数据，慎用）
```

**修改 `.env` 后让配置生效**：

```bash
docker compose -f docker-compose.yml up -d --build     # 会按新环境变量重建 backend/frontend
```

数据持久化：PostgreSQL 数据保存在命名卷 `pgdata`，只要不执行 `down -v`，容器/镜像重建都不影响数据。升级时迁移在 `backend` 启动阶段自动执行（`alembic upgrade head`）。

## 6. 更新（全过程）

更新 = 拉取新代码 + 重建镜像。数据库迁移**自动执行**，但更新前务必先备份（见第 7 节）。

### 6.1 更新前：备份

```bash
# 让 .env 变量在当前 shell 可用（也可把下方 hpf / hpf_work 直接换成你的实际值）
set -a && source .env && set +a

# 备份数据库（最稳妥）
docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > hpf_backup_$(date +%F).sql

# 备份 .env（配置）
cp .env hpf_env_$(date +%F).bak
```

> 若用卷级整体备份，先 `docker compose down`，再 `sudo tar czf pgdata.tgz /var/lib/docker/volumes/<项目名>_pgdata/_data`。

### 6.2 拉取新代码

```bash
git pull                         # git 方式
# 或重新下载 Release 并解压覆盖
git log --oneline -5             # 看本次变更
```

> 若本地改过 `docker-compose.yml` 等文件，`git pull` 可能冲突：先 `git stash` 或 `git checkout -- <文件>` 还原为官方版本再拉取。

### 6.3 重建并应用

```bash
docker compose -f docker-compose.yml up -d --build
```

- Compose 会用新代码重新构建 `backend`/`frontend` 镜像并重建容器。
- `backend` 启动时执行 `alembic upgrade head`：若新版本带了数据库迁移，会**自动应用**；日志里能看到 `Running upgrade ...`。

确认迁移成功：

```bash
docker compose logs backend | grep -i alembic
docker compose exec backend alembic current    # 查看当前迁移版本，应为最新 revision
```

### 6.4 验证更新

```bash
curl http://localhost:8080/api/health          # → {"status":"ok"}
# 浏览器登录，确认历史项目/任务/开发记录都在
docker compose ps                              # 全部 healthy
```

### 6.5 回滚（谨慎）

代码回滚：

```bash
git checkout <上一个稳定版本tag或commit>
docker compose -f docker-compose.yml up -d --build
```

数据库回滚（**通常不推荐，优先从备份恢复**）：

```bash
# 仅在确知迁移可安全回退时：
docker compose exec backend alembic downgrade -1    # 回退一个版本
```

> ⚠️ 风险提示：回滚有数据损坏/丢失风险。若新迁移改了表结构且已写入新数据，单纯 `downgrade` 可能失败或丢字段。**回滚首选"从 6.1 的备份恢复"**，而非数据库降级。

## 7. 备份与恢复

### 7.1 自动备份（内置 sidecar 服务）

生产编排已内置 `backup` 服务（`postgres:16.6-alpine`），每天自动执行 `pg_dump`、gzip 压缩、保留 7 天：

- 备份文件落在宿主机 `./backups/` 目录（命名 `hpf_YYYY-MM-DD_HH-MM-SS.sql.gz`）
- 无需额外 cron，随 `docker compose up -d` 启动
- 只读挂载 `pgdata` 卷，不影响主库写入

查看备份状态：

```bash
docker compose logs -f backup
ls -lh backups/
```

### 7.2 手动触发备份（可选）

```bash
# 即时生成一次备份
docker compose exec backup sh -c 'pg_dump -h postgres -U "$POSTGRES_USER" -d "$POSTGRES_DB" | gzip > /backups/hpf_$(date +%F_%H-%M-%S).sql.gz'
```

### 7.3 恢复（使用脚本）

提供 `scripts/restore.sh`，自动完成：停应用 → 起库 → 清 schema → 导入备份 → 起全栈（含迁移对齐）。

```bash
# 列出可用备份
ls backups/

# 恢复（交互确认，自动处理 .gz/.sql）
./scripts/restore.sh backups/hpf_2026-08-26_03-00-00.sql.gz
```

脚本会：
1. 停止 `backend`、`frontend`（保留 `postgres`、`backup`）
2. 等待 postgres 就绪
3. `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`
4. 解压/直读备份导入
5. `docker compose up -d --build` 起全栈（alembic 自动对齐）

> 备份文件名中的用户/库名以 `.env` 为准（`POSTGRES_USER`、`POSTGRES_DB`），脚本会自动读取。

### 7.4 卷级备份（整机快照式，备选）

停机后直接打包数据卷目录（路径含 compose 项目名，可用 `docker volume ls` 查）：

```bash
docker compose down
sudo tar czf pgdata_$(date +%F).tgz /var/lib/docker/volumes/*_pgdata/_data
```

适合整机迁移或灾难恢复；日常建议用 7.1/7.3 的逻辑备份。

## 8. 排障

| 症状 | 排查 |
|---|---|
| 前端 502 Bad Gateway | `backend` 未就绪：`docker compose logs backend`；确认 `postgres` 健康检查通过（`docker compose ps` 中 postgres 状态 healthy） |
| 表不存在 / 迁移报错 | 看 `docker compose logs backend` 里 `alembic upgrade head` 输出；手动进容器 `docker compose exec backend alembic current` 看当前版本 |
| 登录后 401 | 容器与宿主机时钟不同步导致 JWT 校验失败；`sudo timedatectl sync` 或重启容器 |
| 端口被占用 | 改 `.env` 的 `FRONTEND_PORT`；dev 模式改 `docker-compose.override.yml` 端口；`sudo lsof -i :8080` 查占用 |
| 数据库连不上 | `docker compose -f docker-compose.yml up -d postgres` 后重试；`docker compose logs postgres` 看是否密码/权限问题 |
| 密码报错 bcrypt 兼容 | 锁定 `passlib[bcrypt]==1.7.4` + `bcrypt==4.0.1`（见 `backend/pyproject.toml`） |
| MCP 接入 401 | API Key 无效/已撤销；在「API Keys」页确认 Key 状态，或用 `/keys/exchange` 换 JWT 验证 |
| MCP 报 host 不允许 | `MCP_ALLOWED_HOSTS` 未包含访问域名；填入对外域名后 `docker compose -f docker-compose.yml restart backend` |
| 更新后页面白屏 | 前端静态资源未刷新：硬刷新（Ctrl/Cmd+Shift+R）；确认 `docker compose -f docker-compose.yml up -d --build` 已重建 frontend |
| 磁盘占满 | 清理无用镜像 `docker image prune -f`；确认 `pgdata` 所在分区空间 |

## 9. FAQ / 速查

```bash
# 启动（含构建）
docker compose -f docker-compose.yml up -d --build

# 停止（保留数据）
docker compose down

# 看状态
docker compose ps

# 看日志（跟随）
docker compose logs -f backend

# 健康检查
curl http://localhost:8080/api/health

# 进后端容器排错
docker compose exec backend sh

# 应用数据库迁移（手动）
docker compose exec backend alembic upgrade head

# 查看当前迁移版本
docker compose exec backend alembic current

# 重建使 .env 改动生效
docker compose -f docker-compose.yml up -d --build

# 备份数据库
docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup.sql

# 开发模式（热更新，需 compose.override）
docker compose -f docker-compose.yml -f docker-compose.override.yml up --build
```

**开发模式**说明：覆盖文件让 `backend` 挂载源码 + `uvicorn --reload`、`frontend` 跑 `npm run dev`（Vite :8080），适合本地改代码联调；生产部署请用默认的 `docker-compose.yml`。

## 附：前端 nginx 反代要点（`frontend/nginx.conf`）

- `location /`：`try_files $uri $uri/ /index.html` —— SPA 路由刷新/直达回退
- `location /api/`：反代 `http://backend:8000`，**关闭缓冲**（`proxy_buffering off`）以保 SSE 实时推送
- `location /mcp`：反代 `http://backend:8000`，MCP 也走 SSE，需关闭缓冲 + 长超时
- `location /assets/`：静态资源 7 天缓存

同源反代使生产环境**无 CORS 问题**；`backend` 容器名由 compose 服务名解析。
