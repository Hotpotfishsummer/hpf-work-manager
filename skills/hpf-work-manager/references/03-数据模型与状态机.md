# 03 · 数据模型与状态机

> 数据模型对应关系型数据库中的 8 张表。所有业务表都带 `owner_id`（用户）隔离——
> AI 工具只会看到/操作**当前认证用户**自己的数据。

## 1. 实体关系总览

```
User (1) ──< Project (1) ──< Milestone (1) ──< Task
                 │                 │
                 ├──< TaskDependency (Task 之间多对多)
                 ├──< DevSession (1) ──< DevLog
                 └──< DevLog
User (1) ──< ApiKey
```

- 删除项目 → 级联删除其任务、里程碑、DevLog、DevSession。
- 删除里程碑 → 其下任务保留，`milestone_id` 置空（SET NULL）。
- 删除任务 → 相关依赖记录级联删除。

## 2. 表与字段

### projects（项目）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 主键 |
| `owner_id` | int | 所属用户（隔离） |
| `name` | str ≤120 | 必填 |
| `description` | str ≤500? | 可空 |
| `status` | str | `active` / `archived`，默认 `active` |
| `start_date` | date | 可空 |
| `end_date` | date | 可空 |
| `created_at` | datetime | 服务端默认 |

### milestones（里程碑）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `project_id` | int | `project_id` 外键（级联删除） |
| `name` | str ≤120 | 必填 |
| `due_date` | date | 可空 |
| `status` | str | `active` / `done`，默认 `active` |
| `created_at` | datetime | |

### tasks（任务）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `project_id` | int | `project_id` 外键（级联删除） |
| `milestone_id` | int? | 外键（删除时 SET NULL） |
| `name` | str ≤200 | 必填 |
| `description` | str ≤1000 | 可空 |
| `status` | str | `todo` / `in_progress` / `done`，默认 `todo` |
| `priority` | str | `low` / `medium` / `high`，默认 `medium` |
| `progress` | int | 0-100，默认 0 |
| `start_date` / `due_date` | date | 可空 |
| `completed_at` | datetime | 由状态机自动维护 |
| `estimated_hours` | int | 预留（工时加权），可空 |
| `created_at` | datetime | |

**派生字段（不落库，由后端实时计算）**：`overdue` —— `status != done` 且 `due_date < 今天`。

### task_dependencies（任务依赖）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 主键 |
| `task_id` | int | 依赖方（外键，级联删除） |
| `depends_on_task_id` | int | 被依赖方（外键，级联删除） |

语义：`task_id` **依赖** `depends_on_task_id`（后者是前置任务）。`(task_id, depends_on_task_id)` 唯一。

### dev_sessions（开发会话）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `project_id` | int | `project_id` 外键（级联删除） |
| `title` | str ≤120 | 可空 |
| `started_at` | datetime | 创建时默认 |
| `ended_at` | datetime | `end_dev_session` 时盖章 |
| `summary` | text | 收口总结，可空 |
| `author` | str | 创建者（`web` 或用户名） |
| `created_at` | datetime | |

### dev_logs（开发记录）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `project_id` | int | `project_id` 外键（级联删除） |
| `session_id` | int? | 所属会话（删除时 SET NULL） |
| `entry_type` | str | `progress` / `difficulty` / `todo` / `decision` / `blocker` / `milestone` / `note` |
| `status` | str | `open` / `done`（仅 todo/blocker 使用） |
| `severity` | str? | `low` / `medium` / `high`（仅 difficulty/blocker 使用） |
| `title` | str ≤200 | 必填 |
| `content` | text | 可空 |
| `related_task_ids` | JSON | 本项目内任务 id 数组 |
| `git_ref` | str ≤100 | commit/分支名，仅溯源引用 |
| `author` | str | 记录者 |
| `created_at` / `updated_at` / `resolved_at` | datetime | `resolved_at` 在标记完成时盖章 |

### users / api_keys
- `users`：`id, username(唯一), email(唯一), hashed_password, created_at`。
- `api_keys`：`id, user_id, name, key_hash(HMAC-SHA256，唯一), prefix, revoked_at, last_used_at, created_at`。
  - 明钥 `hpf_<6位hex>_<64位hex>` 仅在创建时返回一次；`revoked_at` 非空即视为已撤销。

## 3. 任务状态机

`apply_status_transition`（REST 与 MCP 共用同一逻辑）：

| 输入 `status` | 自动结果 |
|---|---|
| `done` | `progress = 100`；`completed_at = now`（已盖章则保留原时间） |
| `todo` / `in_progress` | `completed_at = null` |

附加规则：
- `status != done` 时，`progress` 写入生效并钳制在 **0-100**。
- `status = done` 时，`progress` 写入被**忽略**（始终 100）。

## 4. 关键派生算法

| 指标 | 算法 |
|---|---|
| 项目进度 `progress` | `已完成任务数 / 总任务数 × 100`（1 位小数，实时计算，不落库） |
| 延期 `overdue` | `status != done` 且 `due_date < 今天`（实时派生） |
| 延期天数 `days_late` | `今天 - due_date`（天数） |
| 燃尽图 | 期望线 = 项目起止日从总任务数线性降为 0；实际线 = 每天剩余任务数（基于 `completed_at` 按日累计） |

## 5. 数据隔离

- 所有查询都按 `owner_id`（项目）或 `join Project.owner_id`（任务/里程碑/DevLog/会话）过滤。
- 访问不属于当前用户的数据 → 报错"不存在"（而不是"无权限"），避免信息泄露。

## 6. 环境相关

- 本地默认 `DATABASE_URL` 指向 PostgreSQL `hpf_work` 库；首次启动自动执行 `alembic upgrade head` 建表。
- 预留未实现：RBAC 权限、工时加权进度（仅 `estimated_hours` 字段）、进度快照表、多用户共享项目。
