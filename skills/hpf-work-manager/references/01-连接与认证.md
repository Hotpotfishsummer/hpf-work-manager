# 01 · 外部 Agent 接入与 MCP 工具导入全景指南

本文档专门指导外部 AI 编码 Agent（包括 **Claude Code**、**Cursor**、**Antigravity**、**Windsurf**、**Cline / Roo Code**、**dsh** 等）如何无缝导入 HPF Work Manager 的 44 个 MCP 工具，并遵循「双重认证 / 安全外驱」协议进行自主项目推进。

---

## 1. 网络拓扑与 MCP 端点矩阵

HPF Work Manager 基于 **Streamable HTTP**（MCP 官方标准的 Server-Sent Events 流式传输规范），支持长连接与实时会话，无需依赖 stdio 本地子进程启动，可通过网络跨机器透明调度。

| 环境场景 | MCP 端点 URL | 适用客户端 | 鉴权要求 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **Tailscale 专网 (推荐)** | `http://100.69.225.112:8088/mcp` | 笔记本/工作站等异地 Agent | 免鉴权（自动 admin）或携带 Key | 跨节点无缝访问，开箱即连 |
| **服务器宿主本地 (Local)** | `http://127.0.0.1:8088/mcp` | 运行在 Manjaro 上的 dsh / CLI | 免鉴权（自动 admin） | 极低延迟，本地容器直接回环 |
| **开发容器直连** | `http://localhost:8000/mcp` | 后端容器内部或调试工具 | 免鉴权 | 绕过 Nginx 反向代理 |
| **公网域名 / 反向代理** | `https://<你的域名>/mcp` | 公网外部 Agent / 移动端 | 强制 API Key / JWT | 必须配置 HTTPS 证书 |

> **DNS 防重绑定与 Host 头说明**：
> 服务端对 Host 请求头进行了保护。若通过 IP 访问（如 `100.69.225.112` 或 `127.0.0.1`），已默认放行；若自建域名反代，请确保域名已加入服务端的 `MCP_ALLOWED_HOSTS` 或 `CORS_ORIGINS` 配置中。

## 2. 认证模式与权限机制

HPF Work Manager 提供两种灵活的认证鉴权机制：

### 2.1 内网免鉴权模式（Zero-Friction Intranet Mode）
- **触发条件**：请求来自内网/Tailscale 或未携带任何 `Authorization` 请求头。
- **行为**：服务端内部中间件（`MCPAuthMiddleware`）会自动将操作身份回退并绑定为默认最高权限用户 `admin`。
- **优势**：外部 Agent 导入时**零配置门槛**，仅需填写 URL 即可直接生效，极适合单人高频开发和本地多 Agent 调度。

### 2.2 API Key 独立审计模式（Production / Multi-User Mode）
- **触发条件**：请求携带 `Authorization: Bearer <API Key>`。
- **获取方法**：
  1. 打开 HPF Work Manager 网页端（`http://100.69.225.112:8088`）。
  2. 导航至「API Keys」页面 ➜ 点击「新建 Key」➜ 输入 Agent 标识（如 `claude-code-macbook` 或 `cursor-dev`）。
  3. 复制生成的唯一密钥串（格式：`hpf_ab12cd_<64位Hex>`）。
- **优势**：每个外部 Agent 具备独立操作审计日志，可单独撤销/吊销，互不影响。

## 3. 主流外部 Agent 客户端导入配置

### 3.1 Claude Code CLI

#### 方式 A：命令行一键导入（最快捷）
```bash
# 1. Tailscale 局域网免鉴权一键接入
claude mcp add --transport http hpf-work-manager http://100.69.225.112:8088/mcp

# 2. 或携带 API Key 导入
claude mcp add --transport http hpf-work-manager http://100.69.225.112:8088/mcp \
  --header "Authorization=Bearer hpf_ab12cd_你的密钥"
```

#### 方式 B：项目根目录 `.mcp.json`（随项目代码共享）
在任何项目的根目录下创建 `.mcp.json`：
```json
{
  "mcpServers": {
    "hpf-work-manager": {
      "type": "http",
      "url": "http://100.69.225.112:8088/mcp"
    }
  }
}
```

#### 方式 C：全局配置 `~/.claude.json`
在用户主目录下的 `~/.claude.json` 中添加：
```json
{
  "mcpServers": {
    "hpf-work-manager": {
      "type": "http",
      "url": "http://100.69.225.112:8088/mcp",
      "headers": {
        "Authorization": "Bearer hpf_ab12cd_你的密钥"
      }
    }
  }
}
```

## 4. 外部 Agent 行动准则与 Prompt / Rule 模板

为了确保外部 Agent（尤其是认知能力较浅的小模型）不偏离轨道、严格遵循工作流，请将以下指令片段加入到项目的 **`.cursorrules`**、**`CLAUDE.md`** 或 **Agent System Prompt** 中：

````markdown
### HPF Work Manager 协同驱动守则
你的开发行为必须与 HPF Work Manager 紧密协同，严格遵守以下操作协议：

1. 【开工感知】：会话开始时，必须首先调用 `get_manager_status()` 获取管理器驱动模式（双重认证 DUAL_CERTIFIED 或 外部单驱 EXTERNAL_DRIVEN）。
2. 【任务获取/提报】：
   - 优先调用 `get_next_steps(project_name)` 获取当前高价值推进任务。
   - 若要新增任务，必须调用 `propose_task_plan(project_name, tasks=[...], auto_create=True)` 提交提案进行交叉审查。严禁臆造不存在的架构或超长工期。
3. 【编码过程随手记】：
   - 遇到重大技术决策调用 `log_decision`。
   - 遇到阻碍调用 `log_difficulty` 或 `log_blocker`。
4. 【结项核销（防假交付）】：
   - 严禁在未经过实测或未提交 git commit 时标记任务完成！
   - 必须调用 `verify_and_complete_task(task_id, git_ref, verification_evidence)` 提交真实的 Git Commit Hash 以及详细的单元测试/curl 验收凭据。
````

## 5. 实时同步与事件广播（SSE）

AI 工具每次调用 MCP 写操作后，后端会向该项目的所有 SSE 订阅者广播事件，Web 前端自动实时刷新：

```http
GET /api/events/stream?project_id=1
```

事件示例：
```
event: project-update
data: {"type":"updated","entity":"task","entity_id":42,"project_id":1,"ts":"2026-10-15T19:20:00+00:00"}
```

多台机器上的多个外部 Agent（如 MacBook 上的 Claude Code 与 Windows 上的 Cursor）连接同一服务时，任务进度与 DevLog 记录实时一致。

## 6. 连通性测试与快速排障

### 6.1 连通性快速验证

#### 测试 1：curl 探针（验证 HTTP / SSE 端点存活）
```bash
curl -i -X POST http://100.69.225.112:8088/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc": "2.0", "id": 1, "method": "tools/list", "params": {}}'
```
*预期输出*：HTTP 200，并返回包含 44 个工具的 JSON-RPC 列表。

#### 测试 2：Python 客户端单行测试
```bash
python -c '
import asyncio, httpx
async def ping():
    async with httpx.AsyncClient() as client:
        r = await client.post("http://100.69.225.112:8088/mcp", json={"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}})
        print("Status:", r.status_code, "Tools count:", len(r.json().get("result", {}).get("tools", [])))
asyncio.run(ping())
'
```

### 6.2 常见错误与排查清单

| 现象 / 报错 | 根本原因 | 解决方案 |
| :--- | :--- | :--- |
| **`400 Invalid Host header`** | 外部客户端请求携带了未授权的域名/Host | 将域名加入服务端的 `MCP_ALLOWED_HOSTS`，或直接使用 Tailscale IP `100.69.225.112` |
| **`401 Unauthorized`** | 提供了失效或错误的 API Key | 检查 Header 是否有多余空格，或在内网场景下直接**省略 Authorization 请求头**走免鉴权模式 |
| **连接超时 / 无法建立 SSE 流** | 反向代理开启了 response buffering | 确保 Nginx 中配置了 `proxy_buffering off;` 和 `chunked_transfer_encoding off;`（当前镜像已预置） |
| **`502 Bad Gateway`** | 后端 Docker 容器未完全启动 | 检查容器状态：`ssh manjaro "docker ps"` 确认 `hpf-work-manager-backend-1` 状态为 healthy |
